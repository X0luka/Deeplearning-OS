# Deeplearning-OS

本地论文阅读、GitHub 源码阅读与跨资料问答工作台。项目包含 Reader、Wiki 和统一助手；原始资料、笔记与配置保存在本机实例中，模型请求会把相关问题和资料片段发送给你配置的 API 服务商。

> **项目状态：实验性公开源码预览；截至 2026-10-10，暂停主动功能开发。**
> 可以自行研究、修改和尝试使用，但不是稳定正式版，也不承诺更新、安全响应或问题修复时限。Issue/PR 可用于记录问题和贡献，未必及时处理。
> **已知重要问题：独立 Docker 实例的真实 DeepSeek 跨产品问答曾长时间等待后以 `model_finish_missing` 失败，目前没有闭环验收通过的证据。CI 通过不等于真实模型问答可靠，也不等于答案准确。**

## 能做什么

| 功能 | 当前范围 |
|---|---|
| Reader | 导入支持的论文 URL 或上传 PDF，阅读原文、生成中文通读、记录笔记与阅读位置、导出 |
| Wiki | 导入公开 GitHub 仓库的固定提交，索引源码、生成主题说明和架构图、查看引用与导出；不执行被导入仓库的代码 |
| 统一助手 | 围绕论文或仓库提问，在允许的资料范围内跨 Reader/Wiki 检索，保存会话与引用 |

Python、JavaScript/TypeScript 有专门结构解析；其他语言主要提供原文与检索，不能视为同等质量支持。URL 导入不是任意网站爬虫：登录、付费、访问限制和站点结构变化均可能导致失败。

## 安装前须知

- 当前 Docker 目标为 **Linux x86_64 / amd64**。Windows 可使用 Docker Desktop 的 Linux 容器模式；ARM/Apple Silicon 原生运行未验收。
- 需要 Git、Docker 和 Docker Compose。首次从源码构建需要访问基础镜像、Python/npm 依赖和 PDF/OCR 模型下载站点。
- 尚不提供面向普通用户的一键安装包、预构建镜像分发、自动升级或卸载器。Windows 桌面壳源码保留，但本文优先介绍 Docker＋浏览器方式。
- 完整镜像在已有本机测量中，Docker 列表显示约 **5.44 GB**；这不是首次网络下载量。建议预留 **15–20 GB** 空闲磁盘容纳构建、更新和初期数据，大量论文/仓库另需空间。
- 当前 Compose 上限为 **4 GiB 内存、2 CPU**。历史轻负载容器约 182 MiB，不包含 Docker/WSL/浏览器，也不是 PDF 峰值。电脑建议 16 GB 内存；8 GB 可尝试，但不是已验证的最低配置。复杂 PDF 可能触发内存保护和暂停。
- 使用云端模型与当前 CPU PDF/OCR 环境不要求独立显卡。需要自行配置 API、承担服务商费用；本项目不提供免费额度或密钥。

## 从源码启动

```sh
git clone https://github.com/X0luka/Deeplearning-OS.git
cd Deeplearning-OS
docker compose up -d --build
docker compose ps
```

等 `app` 服务健康后打开：

- 工作台与模型设置：http://127.0.0.1:18877/settings/models
- Wiki：http://127.0.0.1:18878/
- Reader：http://127.0.0.1:18879/

这些是新安装默认端口。维护者历史测试实例的 19877–19879 不是默认配置。端口冲突时按 [Docker 指南](docs/DOCKER.md) 为本项目配置三个不同端口，不要停止其他应用抢占端口。

默认 `full` 镜像包含增强 PDF/OCR 环境。`core` 仅用于快速工程验证，不等价于完整用户版本。首次构建慢或下载失败时先检查 Docker 的网络；应用设置里的代理不控制镜像构建下载。

## 配置 API 与日常使用

1. 打开模型设置，添加连接，填写服务商的 API 基础地址、自己的密钥并选择模型，然后保存。优先尝试 DeepSeek；官方基础地址可填 `https://api.deepseek.com`。以服务商实际提供的模型为准，不把完整 `/chat/completions` 请求地址当作基础地址。
2. 模型目录读取成功仅证明目录接口可访问，不代表生成接口或回答质量通过。通用 OpenAI 兼容入口存在，但其他服务商未全部验证；“兼容”不保证所有参数和工具调用行为一致。
3. 编辑连接可修改地址、密钥和模型；删空密钥并保存会清除密钥。删除连接会解除相关配置引用，需要重新选择可用连接；不会因此删除论文或会话。
4. Reader 中粘贴受支持论文链接或上传 PDF，待解析后阅读原文、使用中文通读、笔记或助手。PDF 解析与中文生成是不同阶段，前者可能占用较多 CPU/内存，后者可能产生 API 费用。
5. Wiki 中导入公开 GitHub 仓库，完成索引后生成知识内容。首次研究、补读、审核和失败修订可能产生多次模型请求，不能按最终文章长度估算全部费用。
6. 助手会使用当前资料，并根据权限检索其他资料；需要仅依据某篇论文/仓库时明确限定范围。关键结论请打开引用核对原文和版本。

Gemini 是可选服务商，尚未做真实端到端验收；使用 DeepSeek 的上述主流程不要求先启用 Gemini。不承诺 Gemini 特定能力可用。

## 网络、停止与数据保存

GitHub、论文站点、模型 API 和安装下载源是不同网络通道。某个 API 可访问不代表其他站点可访问；并非所有用户都必须安装代理，取决于所处网络。

需要代理时参考 [网络规范](docs/NETWORK_SPEC.md)。容器中的 `127.0.0.1` 指向容器自身，不能照搬宿主代理地址；Docker Desktop 场景可按实际配置使用 `host.docker.internal:端口`。程序不替用户更改 Clash、网关或系统网络。现有含透明代理环境的成功不能证明无代理网络已通过验收。

```sh
# 暂停，保留数据
docker compose stop
# Docker 引擎就绪后，恢复已有容器
docker compose start
# 若容器已移除，则在同一目录、同一项目名下恢复
docker compose up -d --no-build
```

当前没有配置容器随 Docker 自动重启；打开 Docker Desktop 不等于产品容器已经启动。网页无法访问时先检查 `docker compose ps -a`，再检查实际端口与容器日志；分享日志前脱敏。

资料、API 设置、笔记、进度和对话保存在命名卷中。**不要用 `docker compose down --volumes` 作为日常退出操作，它会删除数据。** 更换 Compose 项目名会使用不同卷，旧数据不会自动迁移。

更新前按 [备份与恢复指南](docs/DOCKER.md#数据停止和升级) 保存备份，并在新实例验证。完整容器备份包含密钥，不要上传到 GitHub、Issue 或公共网盘。不要将个人数据直接合入源码仓库。

## 已验证什么，还有哪些限制

| 范围 | 已有证据 | 不能据此保证 |
|---|---|---|
| 工程 | Linux 干净安装与回归、Windows 桌面编译、core/full 容器构建及数据生命周期均有成功记录 | 所有新电脑、ARM、所有网络及桌面交互 |
| Reader | 公开论文 210 单元真实翻译和导出；15 页增强 PDF 与检查点恢复的限定样本 | 所有版式、扫描件、表格、公式与逐句翻译准确 |
| Wiki | 公开 Python 仓库的正文、图示、引用、导出及恢复样本 | 所有语言、所有仓库、所有架构或流程推断正确 |
| 统一助手 | 独立源码实例有双向问答样本；检索、引用与历史重开有回归 | Docker 真实问答已稳定通过；目前仍有上述 `model_finish_missing` 问题 |

其他重要限制：

- **引用存在不代表结论正确。** Wiki 有模型审核，但不是实际执行验证；聊天最终主要检查引用编号有效性，不逐句独立证明证据支持结论。
- Wiki 的主题组织和固定输出结构可能导致讲解零散；Reader 的长文分批处理可能弱化跨章节关系。完整解析文字不代表图片/公式视觉信息完整。
- 模型可能误判因果、调用顺序、作者动机或实验结论；翻译也可能有术语与推断问题。生成内容适合作为阅读辅助，关键结论需核对。
- 超时、断流或无 usage 回执不等于未产生 API 费用。避免在不确认状态时反复提交长任务。
- 镜像瘦身、完整峰值资源测试和更多真实质量验收尚未实施；暂无后续交付日期。
- 本项目定位为个人本地使用，端口默认只绑定回环地址；不要直接公开到互联网或当作多用户服务。
- 本机管理员/Docker 管理员可以读取实例密钥；“本地保存”不表示对管理员加密。向服务商发送的资料受其条款和隐私政策约束。

历史 CI 红叉会保留，判断当前代码应查看 [Actions 最新运行](https://github.com/X0luka/Deeplearning-OS/actions)。CI 不执行真实付费问答，也不是内容准确性的认证。
