# 独立增强 PDF 环境
2026-09-30：CPU依赖已安装，Docling 2.129.0 / torch 2.14.0+cpu，解析算法沿用原版。
依赖锁在 requirements/pdf-cpu-py312-linux.txt，模型版本与哈希在 assets/pdf-models.lock.json、assets/pdf-ocr.lock.json。
这些是官方外部资源；资产许可证为 Apache-2.0 / CDLA-Permissive-2.0 等，根MIT不覆盖模型资产。完整发布许可审核仍需单独完成。

开发者准备命令见 DEVELOPER_QUICKSTART.md 第2节。准备脚本使用显式 --proxy 参数，不再固定本机端口；有完整缓存时可 --offline。历史 run-pdf-* 包装器用于隔离验收，不是一键安装器。
所有依赖和模型在独立副本 .local/pdf-cpu 内，不写系统Python/用户缓存/原项目环境。
模型目录通过 DOCLING_ARTIFACTS_PATH 传入解析子进程，HF/Docling缓存均指定独立目录；正式解析验收关闭外网。

原版保留的机制：四页起步、内存保护、失败拆页、单页保守模式、已完成页哈希校验与复用、断点恢复。
新增的非恢复型错误：依赖不存在/文件缺失时立即暂停，不浪费时间反复拆页。修好环境后继续。
不会关闭OCR/公式识别、用基础抽取代替增强解析，或把降级结果当作标准模式通过。
测试使用公开15页论文，不上传到外部模型；对已有完成页注入一次受控暂停，检查恢复不重算。

重型测试单独运行；专用进程守护限制总RSS约3000MiB，并在宿主可用内存低于1GiB时停止，1800秒总测试期限，检查点保留。
这些是本机验收保护，未修改产品自身内存策略或现用WSL资源设置；并非零资源占用或硬隔离配额。

## 内核资源隔离补充
仅靠RSS采样无法排除突发分配。重型PDF测试现在还包在独立systemd用户瞬时作用域：
MemoryMax=2300M、MemorySwapMax=0、CPUQuota=150%、IOWeight=10；不改变WSL总配置或其他服务。
退出后作用域自动收集。运行前已用无负载进程验证memory.max与memory.swap.max实际生效。
进程采样保护与宿主1GiB可用内存底线继续保留。子进程被杀只记录SIGKILL，不直接断言宿主OOM。

解析测试专用CPU硬限时改为1800 CPU秒，使其不会早于产品900秒单范围超时误杀工作进程。
此前通用300 CPU秒限时与多次SIGKILL时间吻合；这些记录保留为测试器限制证据，不算产品内存失败。
已经标准完成的1–4页按原哈希和mtime保留复用；因测试器限时产生的降级状态归档，不作为质量通过。
