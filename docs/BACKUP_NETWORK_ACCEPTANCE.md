# 组件备份与离线网络故障验收

本轮只使用合成数据和模拟传输层；原产品、个人资料、真实模型密钥及系统网络设置均不参与。

## 备份恢复修复
Wiki 新备份采用 format 2，包含数据库和 raw/wiki/notes 文件的 SHA256 清单。
恢复前检查文件集合、路径、符号链接、文件哈希及 SQLite 完整性；已有目标一律拒绝。
旧 format 1 仍可恢复，但会明确提示 legacy_backup_has_no_file_checksums；它不能提供新格式的文件哈希保证。
Reader 在创建恢复目标前校验清单、路径与 SQLite 数据库；复制或恢复处理失败时清理本次新建目录。
工作台 SQLite snapshot 的失败清理和拒绝覆盖行为亦有新增回归。

新增合成测试覆盖：正常恢复、已有目标保护、损坏文件、伪造匹配哈希的无效数据库、清单越界、数据库符号链接和模拟磁盘写入失败。
数据库及文件被复制到新的目录后再恢复，不对原数据执行原地覆盖或自动切换。

## 当前范围的限制
这是组件级备份恢复验收。工作台现有 snapshot 只处理指定 SQLite 文件，不自动包含统一助手、模型配置及其他数据库。
后续阶段已新增统一开发实例备份入口：通过受管实例停机与锁保护统一快照，排除凭据，恢复到新实例；8 项合成验收通过，详见 docs/INSTANCE_BACKUP.md。它不自动停止服务，也不覆盖不受管并发写入场景。
Reader 创建备份失败的残留目录处理、磁盘空间预估和大文件资源占用仍需补充。
SHA256 校验检测损坏，不能证明备份来源可信，也不是数字签名。
对其他进程同时恶意修改备份目录的情形未做安全保证。

## 模型网络故障
新增 21 项离线测试覆盖 chat/Gemini 两种协议的连接超时、读取超时、代理失败、连接失败，以及 HTTP 302/401/403/429/500/503。
HTTP 302 不跟随到其他地址；失败请求没有被自动重发。
流式读取中断时保留已经发出的部分文本，输出固定错误码，不把异常中可能出现的密钥带到用户界面。
助手增加明确中文提示：超时、代理、连接、流中断、鉴权失败、权限、限流与服务端故障。
模型目录刷新失败保留旧目录，公开配置不包含合成密钥。
