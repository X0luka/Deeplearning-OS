## 当前执行顺序

1. 基础CI、云端干净安装、Windows构建、Docker完整镜像与恢复已建立并有成功证据。每次修改仍检查对应最新提交；失败先定位，不删断言或改业务质量标准。
2. 真实公开URL轨迹独立于CI。Reader全文已生成导出，Wiki、双向助手及恢复重开已完成限定样本验收；模型输出必须核对内容，不能只看HTTP 200。
3. 完成本机候选体验、真实数据重开和网络故障/恢复；现有网络与原版保持不变。
4. 汇总最终提交、适用检查、未覆盖环境、使用和恢复说明，再交付私有候选。公开和日常升级分别由用户决定。

本机重型测试串行，付费只用于已授权DeepSeek公开/合成材料；无真实密钥进入普通CI。云端运行器的独立任务不占本机WSL内存。

## 几种验证方法分别回答什么

| 方法 | 主要回答的问题 | 当前采用情况 |
|---|---|---|
| 单元/接口回归 | 已经明确写入断言的功能和错误处理，修改后是否仍符合约定 | 已放入每次PR的CI；不代表所有真实内容质量 |
| 浏览器测试 | 页面状态、点击、显示、引用、重开和草稿等交互是否正常 | 固定浏览器回归已自动化，真实资料浏览器轨迹另验 |
| GitHub Actions托管虚拟机 | 干净检出能否安装/构建/运行检查，是否依赖维护者本机路径或缓存 | 已实际运行Linux与Windows；任务结束即清理，费用与账号额度有关 |
| GitHub Codespaces | 给人操作的云端开发工作区，可手动探索安装和界面 | 本轮未创建；干净安装的证据来自Actions，不能称为Codespaces验证。它不是开源项目必需项 |
| Docker | 依赖/资产是否装入镜像，服务/权限/端口/卷及重建恢复是否正确 | 云端core/full已有成功证据；本机网络与真实体验单独检查 |
| 真实模型业务验收 | 实际API、公开论文/源码、翻译/研究/工具检索是否产生可用结果 | DeepSeek分批执行，有调用成本；不放入每次普通CI |
| 人工内容复核 | 关键事实、遗漏、术语、公式和引用是否合乎来源，以及体验是否符合预期 | 工程协作者抽查并留证；模型自审或HTTP成功不能替代这一项 |
| 另一台物理电脑 | 系统安装、驱动、网络和用户配置差异是否影响使用 | 未完成；云端虚拟机和Docker可减少风险，不能覆盖所有差异 |

持续集成CI验证每次变更；持续部署CD会自动把通过的版本发布到使用环境。本项目当前需要前者，尚未配置后者，不会因合并PR自动升级日常产品。
