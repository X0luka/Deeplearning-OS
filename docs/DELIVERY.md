# 开发者候选版交付导航
更新：2026-10-02。仓库 X0luka/Deeplearning-OS 保持私有，许可证 MIT。当前正在完成真实用户轨迹验收，不自动公开或升级现用产品。

## 从哪里开始

1. 首次体验优先阅读 [Docker 指南](DOCKER.md)：从源码构建，浏览器访问本机端口，配置自己的模型。默认完整镜像包含 CPU PDF/OCR 所需环境和资产，首次下载较大。
2. 需要现有 Windows 桌面或源码开发，阅读 [开发者指南](DEVELOPER_QUICKSTART.md)。本次不交付普通用户一键安装包、自动升级或卸载器。
3. 判断是否满足你的实际用途，查看 [验收状态](ACCEPTANCE_STATUS.md)、[用户轨迹清单](PRODUCT_ACCEPTANCE.md) 和 [问题清单](ISSUE_REGISTER.md)。
4. 修改代码前阅读 [贡献约定](../CONTRIBUTING.md) 与 [CI 说明](CI.md)；网络配置见 [网络规范](NETWORK_SPEC.md)。

## 已有交付材料

三组件源码、依赖锁、关键资产校验、Dockerfile/Compose、备份恢复工具、现有桌面构建方式、CI、问题模板和安全反馈说明均在仓库中。测试的具体提交与运行链接见 CI.md；它们不代表任何未来修改自动合格。

2026-09-30 的本地源码 ZIP 和逐文件 SHA256 清单是历史候选，不能当成包含本轮 Docker/CI/检索修复的新版。最终候选应从审查通过的明确 Git 提交导出；源码包排除 .local、密钥、数据库、私人论文、虚拟环境和 node_modules。

## 安装验证的边界

GitHub 托管 Linux 已从干净检出准备依赖；Windows 云端已编译桌面并校验配置；full Docker 已构建并实际运行 HTTP、增强 PDF、重建卷和备份恢复。云端运行器有预装工具，仍不等于任意物理电脑都能运行。

同机独立源码安装和 Windows 原生桌面交互已有证据。本机 Docker Desktop启动遭自身通信端点故障，产品容器尚未运行；全新 Windows/WSL 安装、ARM、其他真实服务商不在已通过范围内。

## 两份产品怎样管理

现用原项目和开源候选各自保存代码、实例数据、配置和备份。测试成功、合并 PR 或更新 GitHub 都不会自动升级现用产品，也不创建第二个桌面快捷方式。

以后升级日常使用版本时，先备份，在独立实例验证迁移和恢复，再明确决定是否替换入口。不要混合两份数据库。Docker 完整备份包含实例凭据，必须私下保存，不能上传到 issue、CI artifact 或源码仓库。

## 公开发布

只有用户明确决定后才改变仓库可见性。保留 MIT 和作者署名，发布说明注明准确提交、已测平台、已知限制及数据恢复方式。历史准备仓库不推送；当前 GitHub 使用清理后的独立历史。当前没有自动部署、镜像推送或公开发布任务。
