# 网络规范与验证范围
更新：2026-09-30。本文描述当前实现；测试结论以本机实测为限。

## 1. 必须具备的网络能力
联网功能需要访问用户选择的论文网站、GitHub 和模型 API。是否需要代理取决于目标站点、地区和网络；Clash 不是产品的强制依赖。
应用不安装代理、不修改系统代理、路由、防火墙、WSL 配置或 TLS 信任。代理工具和可用节点由用户自行提供。
已下载资料、已有回答、阅读位置和笔记属于本地数据；网络失败不应要求清空这些数据。

## 2. 流量和配置边界
| 流量 | 典型目的地 | 使用的设置 |
|---|---|---|
| 桌面和本机组件 | 当前实例的 127.0.0.1 专属端口 | 本机直连、组件鉴权；不向外部代理发送模型密钥 |
| 模型与模型目录 | 用户配置的 API 地址 | 连接自身代理 > 模型通道 > 应用默认 |
| GitHub 源码 | github.com、api.github.com、codeload.github.com；相关功能可能涉及 raw.githubusercontent.com | GitHub 通道 > 应用默认 |
| 论文下载 | arxiv.org、export.arxiv.org 或选择的公开论文网站 | 论文通道 > 应用默认 |
| fake-IP 公共地址确认 | 当前实现可能访问 cloudflare-dns.com | 来源访问的地址校验；其成功不等于下载成功 |
| 开发依赖及 PDF 资产 | 锁文件指定的 Python/npm/模型/SDK 来源 | 安装命令的 --proxy；与应用运行设置分开 |

模型页提供应用默认、模型 API、论文和 GitHub 四项设置，各通道可继承、不使用应用代理或指定 HTTP(S) 代理。
当前不承诺 SOCKS 支持；代理地址中的用户名/密码会被拒绝。保存成功不等于目标站点连通。
设置只写当前实例数据库；受管 Reader/Wiki 在下一次请求读取自己的通道配置。配置读取失败会报错，不静默回退到随机 shell 代理。
客户端使用 trust_env=False；旧独立组件的显式配置入口继续保留。新实例默认不使用应用代理，不预填维护者代理端口。
“不使用应用代理”不能绕开系统 TUN、VPN 或网关，因此不能据此声称纯直连。

## 3. 本机隔离与来源安全
每个开发实例使用自己的三个端口、缓存、业务数据和密钥；端口占用时应报错，不能停止其他服务抢占端口。
Reader/Wiki 返回工作台的链接使用当前实例地址。桌面内部通信不经过外部代理。
来源导入保留环回、私网和保留地址校验及重定向检查；不能为兼容 fake-IP 全面关闭校验。
Reader 对已配置代理的固定 arXiv 主机使用受限处理，其他 fake-IP 情况可能通过公共 DNS 确认。
TLS 证书验证保持开启；禁止把关闭验证作为日常网络解决方案。

## 4. 出错时如何定位
按 DNS → TCP/代理连接 → TLS → HTTP 状态 → 内容/模型协议 → 产品解析顺序定位。
- 连接超时：检查代理进程、监听地址、WSL 到宿主的可达性以及目标服务。
- 401/403：检查 API 地址、密钥、服务权限；不等同于网络断开。
- 429：检查服务商额度或速率限制；模型额度与 GitHub 下载额度不同。
- HTTP 200 但任务失败：继续检查返回格式、正文截断、PDF 内容和引用验证。
- 摘要可访问但 PDF 不可用：分别检查实际下载域名、跳转、登录或付费墙。
- 代理失败：显示错误；不自动切换为直连以绕过已保存的选择。

本机镜像模式曾通过 127.0.0.1:7897 访问 Windows 代理；其他电脑尤其 WSL NAT 模式不能照抄此地址。
先验证自己的代理地址，再分别测试模型、论文、GitHub 三条通道；当前没有一键完成全部分层诊断的功能。

## 5. 重试、取消和费用
下载与模型生成不能共用“失败就无限重试”的策略。传输中断也不能推断提供商未计费。
当前 Wiki engine/knowledge 的 recover_transport 对选定连接、超时及 408/429/5xx 错误最多尝试 3 次，间隔 2 和 5 秒；其他错误直接上抛。
这是现有有界恢复行为，可能重复计费，也不承诺按 Retry-After 精确调度；不能笼统声称所有模型请求都不重试。
本次付费验收包装器在首次供应商错误后停止后续提交，并记录请求台账；这只约束验收，不修改用户日常提示词或模型预算。
知识审核的修订是检查内容后继续工作，与传输失败重发不同。中断恢复复用完成阶段；部分成功后的重试保留已通过主题。
取消任务不保证已经到达供应商的请求不计费。缺少 usage 的调用不估作零费用。

## 6. 当前电脑的只读快照
此前检查显示 WSL mirrored、autoProxy=true、dnsTunneling=true；Windows Meta Tunnel 启用。
Clash 生成配置为 rule、TUN 开启、gvisor、auto-route=true、strict-route=false、fake-ip、mixed-port=7897、allow-lan=false。
这是配置和接口快照，没有读取订阅/控制密钥，也没有逐请求追踪命中节点；不能称全部流量都经过远端代理。
用户后来将 WSL 内存配置改为 8GB，尚待重启；本轮继续使用当时生效的 4GB，不主动重启或切换网络。

- 公开 15 页 PDF 的标准解析和断点复用；此项不是网络长期稳定性的证明。

不关闭用户现用 Clash 来补测试。开发者候选版应公开这些边界，不能宣称所有网络都已兼容。

## 8. 正常功能与输出预算
保留任务实际所需的上下文、引用、分块、恢复和输出质量，不把连通性短测额度当成产品额度。
本次 DeepSeek 测试实例使用 16384 输出额度及默认思考；3000 曾因思考消耗额度而正文截断。原项目配置未更改。
模型官方上限、用户设置和测试批次请求审查阈值是不同概念。没有给日常产品新增验收次数限制或无关措辞约束。
初期网络矩阵、后续质量样本和完整任务属于不同批次；费用与结果分别留档，最终账单以提供商为准。
