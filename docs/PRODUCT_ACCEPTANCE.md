## 原版质量对照的做法

先选定参考源码快照，并整理有代表性的输入、用户认可的旧输出（若有）、提示词、模型参数、分块、上下文、检索、引用、显示与保存行为。
原输出缺失时明确记为缺少证据，不假装已比较。只读核对原源码；所有执行和数据写入都在隔离副本。
同输入比较重要事实、遗漏、引用、恢复和可用性，不要求模型逐字相同，不靠新增苛刻提示词或低 token 配额让测试变便宜。
“灵活性”转为不同问法、连续追问、跨资料检索、工具使用和证据不足时的表现，不承诺任意问题都能正确回答。

## 每次验收需要留下的记录

ID、日期、提交、环境、样本/输入标识、步骤、预期/实际结果、状态、脱敏证据路径或运行链接、关联问题、下一步。
报告不得包含密钥或未经允许的私人文档。付费请求单列次数及可得 usage；没有 usage 不作零费用推断。
示例：U-04 / 待验证 / 原因：只有下载证据，没有完整通读证据 / 下一步：固定一份公开URL样本并核对原版输入路径。
