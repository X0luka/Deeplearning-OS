核心不得包含具体产品名称、默认端口、目录、私有 HTTP 路径、容器名或产品错误文案。扩展可以依赖核心接口和通用适配器，核心不能导入具体扩展；唯一通用装配入口通过 integrations 发现本地扩展。扩展提供 configure(parser)、create(args) -> Integration，描述产品、HTTP 客户端、适配器、服务配置、监督器类型、手动启用策略、默认入口优先级和错误提示。

--products 默认 all；可指定 rag、wiki 或逗号分隔列表；none 不加载任何产品模块。无扩展时只访问宿主档案；归档筛选仍包含已移除扩展的历史产品。扩展选项只在本机 CLI 接受，网页不加载任意模块或命令。保留 --rag-api/--rag-ui/--rag-dir、--wiki-url/--wiki-dir、--no-wiki/--start-wiki 作为扩展自己的兼容参数。共享 Worker 获得同一组选择及绝对数据目录，未选择扩展不创建同步服务。

状态与数据：RAG 默认关闭，显式 start 后 starting→ready/failed；就绪后才健康检查与同步。pause 进入 stopping，排空在途活动后 disabled；Host 重启复位、Worker 重启读取共享活动状态。SQLite 活动代次与跨进程锁保留，事务入队/领取/提交门控保留。产品原始数据归各产品，宿主仅通过 HTTP 导出保存档案，禁止跨库写业务表。

进程：通用 LocalProcesses 负责端口锁、PID 身份、启动/取消和 Worker 维护；RAG 扩展实现 Qdrant 容器规则与 Streamlit 识别。宿主关闭只停止自己的 Worker，独立就绪产品保留。Windows 入口仅启动宿主 runner；runner 使用通用 --autostart，由所选扩展决定自动启动策略。

维护：当前功能线为唯一后续维护基础；旧 core/rag 实现作为 Git 分支历史保留，清理其工作树不删除分支。无需改动产品数据库或新增 schema。验收覆盖静态边界、空扩展、单/多扩展、第三方合成扩展、原 37 项回归和浏览器操作。

历史架构与 RAG-SWITCH-001 约束可从提交 6817143 和对应执行记录追溯；本文件替代旧的分支产品组合方案。
