# 产品范围与第一版目标

> 当前规则（2026-09-14）：RAG 默认关闭，仅手动启用后允许产品活动；以本文 RAG-SWITCH-001 节为准。旧 RAG 专属未验收事项暂停，历史证据保留。

## 用户场景

用户在 RAG 原网页上传自己的 PDF 并问答；即使 AgentOS 当时关闭，会话也由 RAG 保存。AgentOS 启动后读取状态和历史，提供跨产品一致的浏览与归档能力。需要验证调用时，AgentOS 可以通过适配层执行 RAG 查询，但不重复建设原产品业务页面。

## 第一版目标

| ID | 目标 | 完成依据 |
|---|---|---|
| G1 | Ubuntu WSL2 统一产品入口 | 用户只启动 AgentOS；在控制台打开已接入产品时，检查并启动缺失服务，就绪后打开原网页；失败提供原因，无需逐产品手开终端 |
| G2 | 正确调用现有 RAG | 小型获准 PDF 测试集上的同步查询返回回答、引用、interaction_id，并核对原产品记录 |
| G3 | 归档产品原网页会话 | 新增、完成、失败、反馈修改均可同步；关闭 AgentOS 后补同步不丢记录 |
| G4 | 重启后保留档案 | 产品与 AgentOS 重启后记录仍可查；备份恢复演练通过 |
| G5 | 统一适配且不侵入核心 | 核心无 RAG 私有模块依赖；通过契约测试替身检验可扩展性 |
| G6 | 修改与运行版本可追踪 | 每个完整任务有 Git 提交与验证证据，运行版本映射到仓库提交 |

真实第二个产品并非当前交付前置条件。测试替身只证明契约行为，不冒充第二个真实接入。

## 非目标

- 首版不重建 RAG 的上传、切分、问答页面，不替换 Streamlit、Qdrant 或检索算法。
- 不默认收集所有业务数据、向量库或编码工具聊天；文档列表可供状态卡片，全文拉取按需另议。
- 不做自主改代码、自动合并部署、远程训练和多租户。
- 不要求迁移全部产品数据到 AgentOS；先明确归属并覆盖备份。
- 不追求统一技术栈，只统一接入契约。

## 范围解释

产品原网页会话是明确必需范围。现有历史没有入口来源字段，旧记录只能标为 legacy_unknown，不能保证筛出网页记录；保留旧数据，不擅自删除或伪造来源。新版本增加来源标记后默认档案筛选 product_ui；诊断调用标为 agentos_probe，不能混入网页档案。

现有问答数据是逐次 interaction，不等于会话线程。新网页 session_id 的分配、刷新后的恢复由产品补充；旧记录不按时间猜测线程。历史缺失的原文片段不能从当前索引反推为当年的准确证据。

范围编号沿用：R1 独立 WSL 仓库；R2 薄 HTTP 适配与原网页；R3 原网页会话归档；R4 原始资料与历史保留；R5 Git 追踪；R6 确定性运行管理。统一启动属于 G1/R6，不要求当前接入第二个真实产品。


## DW 增量要求
新增独立 GitHub Wiki 产品；范围、模块、版本化接口和验收依照 [Wiki 规范](integrations/github-wiki.md)。既有 RAG 行为和数据保持兼容。

## RAG-SWITCH-001 当前范围覆盖（2026-09-14）
RAG 曾作为接入试用产品，现转为默认未启用的可选产品。此约定覆盖上文默认 RAG 检查/同步及“既有 RAG 行为保持兼容”中的自动活动要求；产品接口、已有数据和启用后的业务边界仍保留。关闭时允许目录展示和旧档案读取，不允许启动、探测、产品调用、同步入队和执行。RAG 本身的配置与检索问题暂停；通用接入、Wiki 和未来工具继续推进。关闭不承诺停止用户独立使用产品时的源端数据写入。

## CORE-002 单主线核心与扩展（2026-09-15）

当前产品为通用核心与可选适配扩展，统一维护于 AgentOS-K。核心包括目录/活动状态、启动监督、同步与档案、网页；RAG/Wiki 扩展负责公开 HTTP 映射及启动配置。产品本身仍是独立仓库。保留 RAG 关闭与 Wiki 使用体验，新增 none 的纯档案模式。清理开发工作树不删除历史分支、产品、备份或会话。


## DATA-001：数据与知识中心
用户确认新增“数据与知识中心”入口与平台数据服务方向，保留现有 Reader/Wiki 应用。首个增量仅将公共档案读取集中为 DataCenter 服务，由通用 Archive 端口提供分页快照；核心不含产品专属逻辑。界面保持简洁，展示已归档问答，不将其宣称为全部材料/笔记。原业务写入与同步协议保持；不新增数据库 schema。知识整理、材料归属迁移按后续阶段接入，不在首批伪造入口。
