## RUN-SERVICE-002 — AgentOS-K 无闪窗常驻

**目标**：由 WSL systemd 直接监督 AgentOS-K，Windows 只在登录时无窗口启动一次 WSL，删除每分钟 PowerShell 轮询。

**前置**：用户已批准平衡恢复策略；Ubuntu systemd 已运行，正式目录为 `${WORKBENCH_SOURCE}`，Linux 用户为 `xix`。

**行动**：新增系统级 `agentos-k.service` 并使用 `xix` 运行现有 runner；安装器先导出并禁用旧任务，再停止旧 runner、启用 systemd unit、注册单次登录任务，验证身份端点后删除旧任务。S4U 无法访问当前用户 WSL 时，使用 GUI 子系统的 `wscript.exe` 以窗口样式 0 启动 WSL，不使用控制台宿主。提供卸载/回滚入口，恢复旧任务时使用安装前导出的 XML。

**交付**：systemd unit、可重复安装与回滚脚本、启动兼容入口、运维说明和本机迁移结果。不修改 HTTP API、监听范围、产品数据或模型设置。

**验证**：unit enabled/active；身份端点与产品页面可用；杀死 service cgroup 后约 5 秒恢复；登录任务连续触发成功且无交互终端；任务 XML 不含 PT1M；至少三分钟无旧任务 PowerShell 启动；现有测试、lint 与 diff 检查通过。

**失败/责任**：Agent 恢复旧任务并报告失败证据；不以隐藏窗口代替删除轮询。人工 `wsl --shutdown` 属于维护动作，不由平衡方案自动恢复。

任务实际状态见 [当前任务](current.md) 与 [执行证据](runs/DEV-001.md)；T01–T03 离线基础已有验证，T04–T10 部分验证，T11 未放行。实施前读 [分工](confirmation-matrix.md)、[证据格式](evidence-template.md) 与仓库规则。代码/测试路径均是拟实施目标，不代表文件已存在。每卡完成需更新实际证据、提交与下一任务状态。
