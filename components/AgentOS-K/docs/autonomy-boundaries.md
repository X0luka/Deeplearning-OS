# AgentOS 自主管理边界

## 当前决定

开发在 VS Code 中进行。Codex CLI/pi 不作为第一版必须实现的双 provider 调度系统。pi 的准确项目/版本尚未确认；只有启用自主诊断或编码能力时才需评估。

| 能力 | 首版行为 | 后续条件 |
|---|---|---|
| 状态检查、历史同步 | 启用后按配置自动运行 | 超时/退避/日志/同步游标 |
| 服务启停 | 用户明确启用托管服务后执行 | 确认服务所有权，不终止无关进程 |
| 自动重启 | 有限次数、退避，频繁失败转告警 | 不能靠重启掩盖迁移或数据错误 |
| 备份 | 配置目标并验证后自动执行 | 不包括自动删除原始资料 |
| 诊断建议 | 首版规则提示，Agent 后续可选 | 清楚限定可读日志和外发内容 |
| 修改代码/提交 | 不由运行中的 AgentOS 自主执行 | 显式任务、隔离分支、测试与审阅 |
| push/PR/merge/部署 | 各阶段需要明确授权范围 | 不由“可以编码”推断发布授权 |

以后引入编码 Agent 时，运行产品 checkout 与开发 worktree 分开。不得让自动修改立即影响正在使用的服务；发布选择已验证提交，迁移和回退单独执行。环境权限与运行监督承担约束，Markdown 不构成安全隔离。
