# AV-002 可解释的架构阅读
状态：本地审查版，等待用户确认；未明确合格，不进行完整性扩展。
## 本轮
现有固定快照的职责语义模型＋分层架构与模块依赖两个并列视图；证据、展开、聚焦、搜索保留邻居、边界关系与导出。
不将目录称为C4容器、不把导入称为运行调用；不加入时序、城市等空入口。
## 技术栈
Python AST/Tree-sitter复用事实；DeepSeek归纳带证据的职责，独立JSON语义产物；FastAPI/SQLite复用服务任务。React/TypeScript/React Flow提供职责卡片和交互，ELK.js Worker提供有向布局；esbuild构建本地静态资源，无额外运行服务。
## 验收
两真实仓库；节点职责/关系证据核验；大图非空；搜索保留邻居；1440x900、1024x768文字与交互；无模型/失败不覆盖旧语义；回归与本地Git不推送。
产品可理解性由用户审查，自动测试不能代替。第一阶段交付后停止。
## 执行
1语义与视图接口 2真实模型产物 3新画布 4回归与浏览器 5本地提交/待审查。

## 实际交付与限制
依赖视图大仓库默认选择文件最多的主要模块，展示其直接关系；最多四个具体对象加一个折叠组。目录保留全部当前范围对象。搜索保留匹配与直接邻居；职责分组展开保留跨组关系。PNG 为当前可见画布，JSON 为当前查询数据，Mermaid 为当前投影。
语义当前覆盖根级聚合模块，每组最多两个关联较多文件的开头样本；深入后的子模块若未单独建模，明确标为待确认，不能继承父模块结论冒充证据。角色为阅读分类，不是部署分层。
React Flow 用于可交互节点与边；ELK Worker 复用有向布局，避免主线程阻塞；TypeScript 检查前端契约，esbuild 输出本地资源；html-to-image 导出当前视窗。保留 Python/FastAPI/SQLite，避免新增运行服务。所有 npm 直接依赖锁定版本；产物提交，运行无需 Node。

## 审查步骤
1 从 AgentOS 打开 Wiki，在快照选择架构视图；先选职责总览或模块依赖。
2 总览点击职责分组，确认模块名称和职责是否帮助理解项目；选择具体模块进入依赖视图。
3 点击关系查看真实导入行，打开职责引用核对解释。搜索或切换依赖方向，核对邻居是否保留。
4 大仓库从目录选择模块；折叠组可列出全部成员。PNG 导出当前视窗，Mermaid 导出当前投影。
5 用户确认“合格”前仅修本轮体验及必要语义，不启动后续完整性扩展。
