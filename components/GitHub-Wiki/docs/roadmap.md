# 产品未来规划

## 独立交互式架构阅读（暂不开放入口）

当前决定：从 Wiki 阅读目录移除独立“架构可视化”入口。正文下已有的 React Flow + ELK 配图、缩放、文字关系、源码证据、生成状态和导出继续保留。独立视图代码及兼容接口暂存，不再作为当前可用功能推荐。

### 希望解决的问题
从一个公开仓库的固定快照出发，帮助读者逐层理解项目职责、核心模块及真实执行流程。流程不依赖仓库名称、特定目录或技术框架，不要求逐仓编写生成脚本或逐图人工发布。仅对已采集源码作出结论。

### 预期交互
- 从核心职责总览进入模块及实现细节，按需展开与收起；目录层级不冒充部署架构。
- 按问题生成聚焦视图，支持功能、关键流程和阅读路线，明确区分依赖关系、实际调用和阅读顺序。
- 点击节点或连线查看解释、条件、内外部边界及固定版本源码依据。
- 搜索模块并查看上下游及跨模块关系，控制展示密度；复杂主题分层，不堆成文件海洋或长链。
- 在图、正文和源码之间定位，后续支持跨图追踪、选中对象带入问答；保留版本一致的引用与导出。
- 普通导入自动规划、生成和审核；局部未完成保留原因及有效成果，人工用于抽查通用规则。

### 重新开放的前提
独立新仓库及既有样本均需对照源码验证总览、模块和关键流程；不能出现重大方向、边界、调用和条件错误。引用存在不等于结论正确，工程测试和自动审核通过不能代替内容验收。需验证亮暗主题、窄屏、布局可读性、证据交互、取消恢复及导出一致。满足这些要求后再考虑开放，暂无承诺日期。

### 数据保留边界
静态分析、知识研究与阶段缓存仍支撑正文及正文配图，不随入口隐藏删除。旧职责说明属于历史生成成果，保留。当前检查只发现共用语法缓存，没有确认可安全删除的独立临时缓存；后续仅清理已证实无引用且可重建的缓存。

历史设计依据：[架构阅读](visual-reading.md)、[问题驱动知识](knowledge-model.md)、[自动配图](automatic-diagrams.md)。这些文档记录历史探索，当前开放范围以产品说明和本规划为准。
