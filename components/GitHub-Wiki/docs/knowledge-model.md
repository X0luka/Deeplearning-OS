# AV-003 面向阅读问题的架构知识
状态：本轮可视化审查版，待用户判断合格；已取消 DeepSeek 总调用次数预算。
## 目标
先建立项目认知，再按功能取证、综合、审核与编图。架构总览和静态依赖独立；正文与总览引用同一版本知识。原始快照不变。
## 技术
复用 Python/Tree-sitter/SQLite 事实索引；Pydantic 校验知识，DeepSeek 分阶段生成；React Flow 渲染主题视图。无需新增向量数据库。模型调用不设总预算，保留单次上下文、输出、超时和无进展终止保护；每阶段缓存与记录。
## 内容门禁
总览一个问题，同层级实体，不堆配置和工具；5—7 个主要节点为目标，最多7节点/12关系，超出重新组织而非缩字；每个节点和关系可追溯。外部服务与客户端库不可混淆。流程以实现证据组织，不能仅重复 README。
## 交付与验收
OpenHands 主样本、AgentOS 回归；实际看图识别项目/边界/关系，再核源码；验证主题展开、依赖跳转、问答、正文和导出一致、失败保留旧版、缓存恢复。本地 Git 不推送；用户“合格”前不扩展其他图形。


## 本轮实现选择
- 事实层继续使用已有 Tree-sitter 和 SQLite：保留可核对的导入证据，不依赖模型猜测静态关系。
- 研究层使用 DeepSeek 与分阶段 JSON 缓存：先定位、按主题检索与补读，再核对展开笔记。失败可复用此前研究；单次输入不超过 96,000 字符、输出 6,500 tokens、150 秒总超时，停止无进展修复。
- Pydantic 约束主题映射、引用、实体边界和关系端点；可疑结果不替换当前知识。
- 编图单独处理：模型只选择功能归并；程序投影已有关系并保留原证据。外部系统单独保留，避免为凑节点数混成服务群。
- React Flow 保留选择、缩放与导出；ELK 提供避障路线和标签坐标，ResizeObserver 在窗口变化时重新适配，避免靠缩小文字解决密度。
- 同一 knowledge_id 生成六个正文页与总览；提问和依赖跳转携带该版本，导出与备份保留相同知识。

## 产品验收边界
自动测试只证明接口、缓存、映射、引用规则等行为。模型审核只提供事实核对的辅助证据。
本轮必须实际打开图检查功能是否易理解、外部边界是否被混淆、连线是否穿过卡片、功能展开与依赖跳转是否可用。
最终“是否好用”仍由用户审查决定；未获“合格”前不开始下一轮完整性扩展。
