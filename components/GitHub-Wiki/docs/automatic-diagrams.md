# Wiki 自动配图

公开仓库导入依次执行快照构建、静态分析、知识生成和 `page_diagrams`。串行队列的任务页提供后续任务链接；知识缓存命中也安排配图检查。普通页面读取、服务启动和状态轮询不会发起模型请求，也不会批量重建历史仓库。

## 生成与审核

六类阅读目录保持不变。每个小节先规划一个具体问题，再选择职责、模块、流程或阅读路线；简单内容和证据不足会记录不配图的原因。当前生成器优先产生 3–5 个节点，限制为 2–6 个节点；兼容旧图的结构协议上限仍为 16 节点、24 边。

生成使用固定快照源码、已有研究线索与静态分析，允许按实际路径补读。文件名、依赖清单和正文不作为调用关系的独立证据。短证据编号只在当前运行内使用，发布时保存文件、行号及原文。

每图经过结构与引用校验、单独的模型源码审核；需要时补读并复核审核意见，以区分事实错误和无关的细节要求。失败允许修正一次并复审，仍失败则保留草稿和原因，合格图独立发布。生成与审核使用当前知识任务配置的模型，是分开的调用步骤，不代表不同模型或人工批准。

审核必须逐项覆盖图的说明、所有节点和所有连线，每项给出判断与有效源码引用；缺项或未核实项不得批准。条件审核检查每个动作所在的 if/else、否定条件和提前返回，不能把互斥分支合为同一输入必经操作。工厂函数、返回实例、外部服务、内部状态分别表达。流程页必须解释具体输入到输出，阅读路线不能冒充调用链。显式重试会把上一轮拒绝意见传回规划和生成，已成功的小节继续复用。

网络超时等供应商错误不自动重发。已完成但格式错误的 JSON 允许一次格式修正。无可用模型时保留源码阅读能力，不生成替代架构理解的目录图。

## 任务与版本

- `GET /api/versions/{id}/page-diagrams`：状态、进度、当前成果和失败原因，无模型副作用。
- `POST /api/versions/{id}/page-diagrams`：沿用写入鉴权，安排或复用目标相同的活动任务。
- 通用任务接口支持取消、显式重试；重启将运行中的任务标为 interrupted。

成果绑定版本、commit、knowledge_id、正文哈希和生成器版本。阶段输出位于版本知识目录的 `page-diagrams/runs/`；显式重试复用匹配的成功阶段。新成果写入独立文件后原子切换 `current.json`。供应商故障保留先前成果；正文或版本不匹配的旧图不展示。

旧版人工批准的 26 张 OpenHands 图继续读取，人工记录不被自动审核覆盖。新的自动成果显示“模型生成并自动核对”。不修改历史正文或用验收样本替换正式成果。

## 阅读与导出

图位于相关正文下方，支持缩放、平移、文字关系列表。点击节点或连线显示该对象解释和固定源码依据。节点按内容计算尺寸，支持横向或纵向布局及分组标签。第一版不实现节点展开、跨图追踪或聊天联动。

页面展示进度、失败原因和手动重试；生成后提供刷新入口，避免打断阅读位置。导出 ZIP 包含 `page-diagrams.json` 与可读的 `page-diagrams.md`，后者列出节点、关系、对象解释及固定 commit 的源码链接。新任务排队时不显示上一轮的完成进度；服务重启使旧页面令牌失效时提示刷新后重试。

## 验证与恢复

运行 `.venv/bin/python scripts/verify_dw.py` 和前端 `npm run check` / `npm run build`。测试覆盖自动串接、缓存、去重、取消、恢复、部分失败、坏引用、旧图和版本隔离。离线测试只能证明工程行为，不能替代真实模型质量验收。

真实验收使用已采集的 AgentOS-K、OpenHands、nanoGPT 固定快照，每仓抽查总览、模块和关键流程。样本使用独立知识 ID 和正文哈希，仅存隔离验收目录；不能被误用于正式全文。具体结果、浏览器证据和恢复回执见本地 `docs/human/README.md`。

本次无需数据库迁移。恢复时在新目录恢复一致性 SQLite 备份和对应 raw/wiki 数据，检查引用与成果绑定后再切换服务；不要覆盖活跃数据库。源码与构建资源可通过本地 Git 提交回退。快照覆盖限制继续有效，未采集代码不在架构理解承诺范围内。
